System Architecture & Traffic Flow

This diagram illustrates how the ML-O11Y SDK captures traffic inline without adding latency, forwards it to the Python collector, and routes it through the Isolation Forest Machine Learning Model for real-time threat detection and dashboard rendering.

sequenceDiagram autonumber participant Attacker as 🕵️ Attacker participant API as 💻 Host API (SDK) participant Ingest as 🛡️ Ingest Server participant ML as 🧠 ML Scorer participant DB as 💾 SQLite DB participant Dash as 📊 Dashboard participant Hook as 🔔 Webhook/Slack Attacker->>API: Malicious Request (Burst/Scan) API-->>Ingest: Async Telemetry (Fire & Forget) Ingest->>Ingest: IP Rate Limiter (Auto-Block?) Ingest->>ML: Extract Features (Latency, Rate) ML-->>Ingest: Risk Score (0-10) & Severity Ingest->>DB: Persist Event & Alert Ingest--)Dash: WebSocket Push (new_event) Ingest--)Hook: High Severity Alert!

1. Zero-Latency SDK

The Python SDK hooks into Flask's `after_request` to capture metrics. It uses background threading to forward data so the host API is never slowed down.

2. Machine Learning

Traffic is scored by a trained Isolation Forest model which scales the output. Normal traffic scores ~0.0, while anomalies spike to 6.0+.

3. Active Defense

When threats are detected, the system auto-blocks abusive IPs at the load balancer level and fires webhooks to alerting systems like Slack.

STEP 4

Add integration code

Copy and paste this ready-to-run snippet into your API application. Notice how only two lines of code are needed! 

from flask import Flask
from mlo11y import SecurityMiddleware

app = Flask(__name__)

# Attach security telemetry middleware (reads SECURITY_SDK_API_KEY from environment)
SecurityMiddleware(app)

@app.route("/")
def index():
    return {"status": "ok", "message": "API active with real-time threat telemetry"}

@app.route("/api/data")
def data():
    return {"data": [1, 2, 3], "secured": True}

if __name__ == "__main__":
    app.run(port=5000)
💡 SecurityMiddleware(app) operates completely out-of-band using an asynchronous worker queue. If the collector ever goes offline, your API traffic is completely unaffected.
STEP 5

Start your application

Launch your application in the terminal where your SECURITY_SDK_API_KEY is configured: 

python app.py
🟢 Expected Startup Log:
* Running on http://127.0.0.1:5000
[mlo11y] Initialized SecurityMiddleware (queue size: 1000, worker: active)

🔧 Troubleshooting Guidance
  • Is your application running? Check your terminal to ensure Flask booted and received a request.
  • Did you set the environment variable? Verify with echo $SECURITY_SDK_API_KEY (or echo $env:SECURITY_SDK_API_KEY).
  • Is the collector accessible? Confirm your app can send HTTP POST to http://localhost:5000/ingest without network proxy blocks.
  • Receiving HTTP 401 Unauthorized? Ensure the API key begins with sec_live_ and belongs to this project.
  • Quick Verification: Click "Send Live Test Event" above to confirm the dashboard pipeline is operational.

Google Gemini AI Threat Analyst

The platform integrates with Google Gemini (gemini-3.6-flash, gemini-3.7-flash) to provide autonomous, multi-tenant incident root-cause analysis and executive PDF reports.

Server-Side Security: The API key is stored exclusively on the server in GEMINI_API_KEY and is never sent to or accessible by client browsers.
Multi-Tenant Isolation: Threat investigations only access chronological telemetry belonging strictly to the authorized project.
Offline Resilience: If the Gemini API is unreachable or rate-limited, the system automatically falls back to deterministic heuristic threat intelligence reports.
