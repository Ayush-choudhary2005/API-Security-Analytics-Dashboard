System Architecture & Traffic Flow

This diagram illustrates how the ML-O11Y SDK captures traffic inline without adding latency, forwards it to the Python collector, and routes it through the Isolation Forest Machine Learning Model for real-time threat detection and dashboard rendering.

sequenceDiagram autonumber participant Attacker as 🕵️ Attacker participant API as 💻 Host API (SDK) participant Ingest as 🛡️ Ingest Server participant ML as 🧠 ML Scorer participant DB as 💾 SQLite DB participant Dash as 📊 Dashboard participant Hook as 🔔 Webhook/Slack Attacker->>API: Malicious Request (Burst/Scan) API-->>Ingest: Async Telemetry (Fire & Forget) Ingest->>Ingest: IP Rate Limiter (Auto-Block?) Ingest->>ML: Extract Features (Latency, Rate) ML-->>Ingest: Risk Score (0-10) & Severity Ingest->>DB: Persist Event & Alert Ingest--)Dash: WebSocket Push (new_event) Ingest--)Hook: High Severity Alert!

1. Zero-Latency SDK

The Python SDK hooks into Flask's `after_request` to capture metrics. It uses background threading to forward data so the host API is never slowed down.

2. Machine Learning

Traffic is scored by a trained Isolation Forest model which scales the output. Normal traffic scores ~0.0, while anomalies spike to 6.0+.

3. Active Defense

When threats are detected, the system auto-blocks abusive IPs at the load balancer level and fires webhooks to alerting systems like Slack.
